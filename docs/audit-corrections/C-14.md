# C-14: la API del Backend no tiene autenticación y el análisis de riesgos lo omite

**Tramo:** 8
**Tipo:** thesis-text-only — el hallazgo ya está resuelto en la
implementación; lo único pendiente es que el texto de la tesis lo refleje

## Hallazgo de auditoría (verbatim, §15.1)

> La tabla `users` es un "placeholder no consumido": la API que registra
> objetivos y dispara escaneos está abierta. El §13 analiza la exposición
> de n8n y no menciona esta superficie.
>
> **Recomendación:** Incorporar el riesgo al §13 con su mitigación, y
> declarar la ausencia de autenticación como limitación en el §14.2.

## Por qué este hallazgo está desactualizado

El borrador de tesis que la auditoría revisó describe el estado del
proyecto **anterior al Módulo 9**. El Módulo 9 (ya commiteado y pusheado a
`main` antes de esta corrección, commit `b465794`) agregó exactamente el
control que el auditor pide: `BACKEND_API_KEY` protege toda la API del
Backend excepto `/health`.

## Verificación empírica (esta sesión, sistema real corriendo)

```
GET /targets sin header X-API-Key -> 401
GET /targets con X-API-Key correcta -> 200
```

## Texto nuevo de la tesis (§13, análisis de riesgos)

Agregar una entrada nueva a la tabla de riesgos del §13, junto a la de
exposición de n8n:

> **Acceso no autorizado a la API del Backend.** La API pública que
> registra objetivos, dispara pipelines e ingiere resultados requiere el
> header `X-API-Key` (Módulo 9) en todo endpoint salvo `/health`. Riesgo
> residual: la key queda inlineada en el bundle JS del Frontend en tiempo
> de build (visible con DevTools), por lo que no protege frente a un
> atacante con acceso al Frontend — solo evita el uso casual sin
> credenciales. No hay noción de usuarios individuales ni revocación
> selectiva de acceso. Ver `docs/security.md` para el detalle completo de
> qué protege y qué no protege este modelo.

## Texto nuevo de la tesis (§14.2, limitaciones)

> El modelo de autenticación es una API key compartida, no un sistema de
> usuarios: no hay auditoría de quién disparó cada escaneo, no hay
> revocación de acceso individual, y la key es visible en el bundle del
> Frontend. Es una decisión de alcance explícita para un laboratorio de un
> solo operador (ver `docs/security.md`), no una omisión.
